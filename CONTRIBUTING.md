# Contributing

Contributions to Unit Converter are welcome. Please follow the
[code of conduct](CODE_OF_CONDUCT.md) in project discussions and reviews.

## Bugs and feature requests

Use the [bug report form](.github/ISSUE_TEMPLATE/bug_report.yml) or
[feature request](.github/ISSUE_TEMPLATE/feature_request.md) template when opening an issue.
The bug report form includes an optional file upload for screenshots, recordings,
logs, and other diagnostics.

For a bug report, include the extension, PowerToys, and Windows versions;
the query or steps that reproduce it; and the expected and actual result.
For parsing or localization problems, include your display language, regional
settings, and relevant extension settings. Remove personal information and
credentials from logs before sharing them.

For a feature request, describe the workflow it would improve and give a
concrete example. For substantial changes, discuss the scope with a maintainer
before investing in a large implementation.

Report security vulnerabilities privately as described in [SECURITY.md](SECURITY.md).

## Development

The [development guide](docs/dev/README.md) is the entry point for prerequisites,
repository layout, builds, automated tests, local deployment, VM testing, and
the detailed engineering references.

Follow the style conventions and validation guidance there, and keep changes focused.
Keep signing keys, credentials, and machine-specific VM configuration local.

## Pull requests

Keep a pull request focused on one problem. Explain the problem, the resulting
behavior, and how you checked it. State any validation you did not run, including
live UI or installation checks when relevant. Include screenshots for visible
UI changes and use the [pull request template](.github/pull_request_template.md).
